# Грабли: AutoCAD 2024 / accoreconsole / СПДС / печать

## accoreconsole

- Запускать **из PowerShell**. Git Bash портит ключи `/i`, `/s`.
- Входной DWG — копия по короткому **латинскому** пути. `.scr` — только **cp1251** (`Write-Scr`): в UTF-8 или ASCII кириллица ломается. Длинные строки в `.scr` ломают ввод, поэтому текст MTEXT режется кусками ≤200 символов (`od_lib.set_mtext`).
- **Несбалансированные скобки** LISP вешают консоль на `(_>`. Проверять заранее (`Test-LispParens`).
- Выход: `(command "_.QUIT" "_N")`, перед ним при необходимости `QSAVE`. Голый `_.QUIT` может зависнуть на «Сохранить изменения?».
- **Нет `layoutlist` и ActiveX** (`vlax-get-acad-object` → nil). Макеты брать из `(dictsearch (namedobjdict) "ACAD_LAYOUT")`: имя — группа 3 перед 350, порядок вкладок — группа 71 объекта Layout. В самом Layout **первая группа 1 — имя набора параметров печати**, а не макета.
- Вывод консоли искажает кириллицу. Для данных писать файл из LISP: `(open f "w" "utf8")`.
- Чертежи Civil 3D открываются ~15 с (модули AECC). Сообщения «Unable to access Shared Pipe Catalog» — не ошибка.
- DXFOUT больших файлов с съёмкой даёт сотни МБ. Для разведки достаточно текстов макетов (`dump_layout_texts.ps1`), полный DXF не нужен.
- В консоли объекты СПДС — `ACAD_PROXY_ENTITY`, правке не поддаются. `arxload mcsenabler.dbx` в консоли не работает.
- Параллельно 10+ консолей на тяжёлых файлах — плохая идея. Запускать по одной.

## Полный acad.exe в пакетном режиме (нужен для СПДС)

- `acad.exe /nologo /b run.scr` **без чертежа**. Файлы открывает сам плагин (`DocumentManager.Open`): если передать DWG в командной строке, модальное окно «Информация о прокси-объектах» заблокирует скрипт. Поэтому на время работы `PROXYNOTICE = 0`, потом вернуть.
- NETLOAD из `.scr`: путь к dll — **латинский** (скопировать dll в Temp). Иначе «????» в пути, плагин не грузится, и AutoCAD молча висит на пустом «Чертеж1». `SECURELOAD` на время 0.
- **Последняя строка `.scr` должна кончаться переводом строки**: иначе последняя команда (например `TXTFIX`) остаётся набранной в командной строке и не выполняется, а AutoCAD молча ждёт. `Write-Scr` дописывает перевод строки сам.
- Сохранять из плагина `db.SaveAs(out, DwgVersion.Current)`. QSAVE/QUIT из `/b`-скрипта могут повиснуть на диалоге. Процесс завершать по метке в журнале (`ALLDONE`).
- **Не запускать одновременно с accoreconsole**: acad.exe падает с «Unhandled Access Violation». Повторный запуск в одиночку проходит.
- AutoCAD пользователя может быть открыт с файлом из того же комплекта. Не трогать: проверить занятость, отложить замену.

## СПДС GraphiCS (MultiCAD .NET API)

- **На новом ПК `TXTFIX` может падать с `FileNotFoundException: mapimgd`, хотя СПДС вручную работает.**
  Выбор профиля СПДС и даже запуск через интегратор CSoft сами по себе не устранили ошибку в проверенном окружении.
  Перед обработкой DWG требуется явно загрузить **сначала `MapiBaseTypes`, затем `mapimgd`** из папки установленного СПДС,
  до JIT-компиляции методов, использующих типы MultiCAD. Это выполняет `SpdsDependencies` внутри `acad.exe`;
  один лишь отложенный `AssemblyResolve` оказался недостаточен. Загрузчик ограничен этими двумя сборками и проверяет
  их идентичность/версию; папка задаётся `RDCI_SPDS_DIR` (по умолчанию штатная папка СПДС 2023).
  Не копировать DLL поставщика в репозиторий и не загружать реальные сборки из внешних тестов/PowerShell.
  Проверено 04.11.2026: `-Dry`, 136 текстовых объектов, `DONE|changed=0|mcs=0`, `ALLDONE`, хеш исходника неизменен.
  Этот тест подтверждает загрузку API и чтение обычных текстов, **не** чтение настоящих объектов СПДС (`mcs=0`).

- Сборки: `C:\Program Files\CSoft\СПДС GraphiCS 2023 x64\mg142x64\mapimgd.dll`, `mapibasetypes.dll`. Документация в `mapimgd.xml` неполная, члены классов смотреть рефлексией (`spds_text\refl_spds.ps1`, Windows PowerShell 5.1).
- Объект по id AutoCAD: `McObjectManager.GetObject(McObjectId.FromOldIdPtr(id.OldIdPtr))`.
  - Таблица `mcsDbObjectTable2` → `McTable`: `t[r,c].Value`, `t.Rows.Count`, `t.Columns.Count`.
  - Многослойная выноска `mcsDbObjectNoteMultilayer` → `Units[i].Text` (заменять элемент новым `McNoteUnit`).
  - Позиционная выноска `McNotePosition` → `FirstLine`, `SecondLine`.
- Порядок правки: `ent.TryModify()` → изменение → `ent.DbEntity.Update()`. Через ActiveX у объектов СПДС только общие свойства (слой, цвет), текста нет.
- После сохранения в полном AutoCAD прокси-графика обновляется: правки видны и при печати из консоли.
- Компиляция без Visual Studio: `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` (C# 5: без `$"…"` и `?.`). Неоднозначность `Cell` (AutoCAD vs Multicad) — писать полное имя.

## Печать в PDF

- `(command "_.-PLOT" "_N" "" "" "DWG To PDF.pc3" "<файл>" "_N" "_Y")` — по сохранённым параметрам текущего макета (CTAB).
- «**Нет подходящего носителя**» в логе означает, что в макете нестандартный формат (например «UserDefinedMetric (1189.00 x 420.00мм)»), которого нет в `%APPDATA%\Autodesk\AutoCAD 2024\R24.3\rus\Plotters\PMP Files\DWG To PDF.pmp`. PMP — JSON после строки-заголовка: добавить запись в `udm.media.description` и `udm.media.size`, имя (`name`) — точно как в макете. Сначала сделать резервную копию PMP.
- Внешние ссылки должны лежать рядом с копией (`Внешние_ссылки\…`), иначе на PDF не будет штампа или подложки. Пути xref в листах обычно относительные.
- PDF из Word: COM `Documents.Open` → `Content.Find.Execute(…, 2)` (заменить всё) → `ExportAsFixedFormat(pdf, 17)`.

## PDF-проверка

- Текст SHX в PDF — векторная графика, не текст. Проверять рендером (pymupdf `get_pixmap(clip=…)`) и смотреть глазами. Учитывать, что крупные картинки показываются уменьшенными.
- Сравнение с прошлой выдачей: число страниц, размеры (`page.rect`), отличия по скоплениям пикселей — `compare_pdfs.py` (не по доле пикселей, см. ниже).
- На повёрнутых листах (А0) прямоугольник клипа считается в неповёрнутых координатах. Проще отрендерить страницу целиком и обрезать картинку.

## Прочее

- Python для чужих файлов запускать с `-I`. Windows PowerShell 5.1 читает `.ps1` без BOM как ANSI: файлам для 5.1 нужен UTF-8 с BOM.
- `Copy-Item` сохраняет время изменения источника. Свежесть PDF проверять не по времени, а по содержимому.
- Сравнение образа файла (`Get-FileHash`) до и после — простой способ доказать, что исходник не тронут.

## Находки при сборке выдач (водопропуски, 15.10)

- **Номер листа бывает полем от имени файла.** У водопропусков: атрибут «НАИМЕНОВАНИЕ» блока «Name» = поле `AcExpr($(substr,$(getvar,dwgname),1,3))`, то есть первые 3 символа имени DWG («003 …» -> 3). Если копию переименовать (`f2.dwg`), поле печатает «#». Поэтому `Copy-DwgToWork` сохраняет латинское начало имени (`003~2.dwg`). Перед «исправлением» атрибута проверить, не поле ли это (xdict -> ACAD_FIELD). Поле не затирать числом. `set_sheet_attr.ps1` — только для настоящих пустых значений.
- **Внешние ссылки в выдаче:** пути бывают на старые папки (`..\..\..\..\Проработки\…`), а в `Внешние_ссылки` выдачи может не хватать файлов (Трассы, съемка). Признаки в PDF: вместо штампа текст «Вн-ссылка <путь>», на планах нет подложки. Проверять перед печатью: список xref с путями (tblnext "BLOCK", флаг 4, группа 1). Лечить так: доложить файлы и перенаправить `-XREF _P <имя> .\Внешние_ссылки\<файл>.dwg` на копии рядом с папкой ссылок.
- Нестандартные форматы листов («UserDefinedMetric (594.00 x 1682.00мм)» и т.п.) переходят с компьютера автора. Добавлять на своём — `add_pmp_size.py "<имя как в макете>"`. Имя формата макета — группа 4 объекта Layout.
- Резервные копии скриптов кладутся в `%LOCALAPPDATA%\Temp\acc\backup\<скрипт>_<дата>`, не в рабочую папку: рабочая очищается при следующем запуске.
- Here-string PowerShell (`@"…"@`) не кончается переводом строки. Всё, что дописывается после него в `.scr`, должно начинаться с `` `n ``, иначе склеится с последней командой.
- **PowerShell не различает регистр имён переменных**: `$C` и `$c` — одна переменная, `$Pmp` и `$pmp` — тоже. В циклах не называть переменные так же, как пути/параметры. 15.10 так затёрся путь временной папки, и PDF легли в относительные папки внутри проекта.
- Сравнение «старый PDF против перепечатки»: попиксельная разница ~0,01% только в штампе — это подписи-картинки (разное сглаживание), содержимое то же.

## Находки 15–17.10 (правки значений, архив, объёмы)

- **Резервная копия может молча не создаться.** 15.10 скрипты писали «заменён (оригинал: …)», а копии части файлов в backup не оказалось
  (`Copy-Item` без `-ErrorAction Stop` не прерывает скрипт). Потеряны оригиналы 4 файлов макетов, 3 файлов «цементно-грунтовой», 1 ГОСТ,
  4А-1 004-005 и В-5А-2 008 до перепривязки (список — `_claude\архив правок 2026-10\README.md` проекта). Теперь все заменяющие скрипты:
  копия с `-ErrorAction Stop` + сверка размера; при ошибке исходник НЕ заменяется. Новые скрипты делать так же.
- **Решать «изменился ли PDF» по доле пикселей нельзя**: правка одного числа на листе А1 (+1885,86 → +2113,10) — 0,0006 % пикселей,
  меньше шума печати. `compare_pdfs.py` ищет **скопления** отличий (склейка соседей `binary_dilation` + связные области ≥ 30 пикс. при 100 dpi)
  и отделяет зону штампа (190×60 мм в правом нижнем углу).
- **Цвет объектов СПДС при печати из консоли** — по прокси-графике, сохранённой в DWG, а не по настройкам пользователя: стрелки уклона «1:1»
  печатаются чёрными вместо серых (`PLOTTRANSPARENCYOVERRIDE=2` не помогает). Поэтому сравнение «PDF пользователя ↔ печать консоли»
  даёт ложные «ОТЛИЧАЕТСЯ» на листах с такими объектами (В-4А-2 л.4). Для R1 сравнивать печать консоли с печатью консоли.
- **Отметки уровня СПДС** (`mcsDbObjectLevelMark`) — значение не в тексте, а в свойствах объекта (`DbEntity.ObjectProperties`, «Text»/«Comment»).
  Обычный поиск текста их не видит; править через `run_txtfix.ps1 -Mode props` (числа сравниваются с допуском 0,0005).
- **Объёмы:** ezdxf не читает 3D-тела SAB этих DWG → объёмы через MASSPROP (`massprop.ps1`, на каждое тело отчёт .mpr).
  Площадь по откосу — TIN (Делоне) по вершинам 3D-линий блока котлована; штриховка проецируется на TIN (`slope_area.py`).
  DXF листов с Civil 3D/съёмкой — 200–300 МБ, ezdxf читает такой ~1–3 мин и ~2–4 ГБ памяти: по одному файлу.
- **Динамические блоки в DXF** — анонимные `*U123`: `layer_stats.py` считает вставки по этим именам; исходное имя блока ezdxf не даёт без разбора XDATA.
- **`python -I` игнорирует `PYTHONIOENCODING`**: при выводе символа вне cp1251 (например «×») скрипт падает с UnicodeEncodeError.
  Скрипты toolkit сами переключают stdout на UTF-8; в pwsh перед запуском: `[Console]::OutputEncoding = [Text.Encoding]::UTF8`.
- **Чужой код бывает в имени макета** (4А-1 л.6 — макет «06_КВ-1_В-5А-1»): штамп и тексты могут быть верны, а вкладка — от копии чужого файла. `find_codes.py` показывает и такие имена.
