# Плейбук: проверка и корректировка РД в AutoCAD

## 0. Правила работы (всегда)

1. **Исходники не трогать, пока не проверено.** Всё — на копиях в рабочей папке (`Temp\acc\…`, латинские имена). Обратно в проект — только при успехе, с резервной копией оригинала.
2. **Сначала тест на одном файле** — самом большом/сложном. Показать результат в PDF (положить рядом с проектом в `_claude`), получить «ок» — потом пакет.
3. **Выдача — новая папка**, существующие выдачи не перезаписывать без нужды: `<дата> - <шифр>\DWG` + `\PDF`.
4. **Файлы, открытые у пользователя, не перезаписывать.** Проверять открытием на запись (`Test-FileFree`), `.dwl` не верить. Отложить и заменить, когда закроет.
5. **AutoCAD пользователя не автоматизировать.** Пакетная работа — accoreconsole или отдельный `acad.exe /b`. Их не запускать одновременно.
6. **Объекты СПДС не взрывать**, если можно править через API (`spds_text`). Взрыв — только с согласия.
7. **Решения пользователя и найденные ошибки записывать** в `<проект>\_claude\README.md` (с датой). Ошибки на листах, не входящие в задачу, — в «открытые вопросы», не исправлять молча.
8. Уточняющие вопросы — с вариантами, рекомендуемый первым; не спрашивать то, что можно выяснить из файлов.

## 1. Разведка (с неё начинается любая задача)

- Структура папок: где последняя выдача, где рабочие файлы, где `Внешние_ссылки` (бывают во вложенной «Новая папка»).
- Тексты по макетам: `dump_layout_texts.ps1 -Dwg лист.dwg` → номер листа в штампе (MTEXT вида «Т7.12»), шифр/наименование (обычно во внешней ссылке `штамп.dwg` — одна на все листы папки), заголовки видов, типы объектов (`ACAD_PROXY_ENTITY` в консоли = объекты СПДС).
- Текст PDF с SHX-шрифтами не извлекается — читать **рендером** (pymupdf) с кропом: штамп, спецификации, ведомости работ.
- Выписать значения, из которых будет строиться документ (площади, объёмы, длины, марки), с указанием, откуда взято.

## 2. Лист «Общие данные» по образцу (`toolkit\od\`)

1. Выбрать образец ОД того же типа (лучше уже проверенный пользователем). Таблицы СПДС в образце должны быть **взорваны** (в консоли они не редактируются) — это делает пользователь.
2. Найти handle-ы: MTEXT «Общие указания», MTEXT «скрытые работы», атрибуты «Лист»/«Листов»; в `штамп.dwg` — наименование и шифр. Сетку ведомостей (X колонок, Y верха) — по DXF образца.
3. Скопировать `example_gen_od.py` в `_claude` проекта, заполнить HANDLES/GRID/DATA, текст указаний (переписать п.«Конструктивные решения», нормы, скрытые работы под конструкцию — не тянуть чужие решения из образца).
4. `build_od.ps1 -SampleDwg … -Gen … -Key …` → смотреть `check.pdf` (FAIL-handle = нет такого объекта в образце; проверить, что ведомости не вылезли за рамку).
5. Выдача: ОД + `штамп.dwg` (новый шифр подтянется на все листы папки) + обложка (.doc — копия с заменой фраз через Word COM, PDF — `ExportAsFixedFormat(…,17)`; заменять фразы целиком).
6. Ведомость чертежей — по фактическим листам и новой нумерации; ведомость спецификаций — листы, где есть спецификации; ссылочные — по реально использованным в спецификациях ГОСТ/СТО/ТУ.

## 3. Перенумерация листов

- Номера листов в штампах — обычно MTEXT в макете. `renum_stamp.ps1 -Files … -Prefix "Т7." -Map @{старый=новый} -PdfDir …` (сначала без `-Apply`).
- Имена DWG привести к нумерации: `NNN Название.dwg`, несколько макетов — `004,005 Название.dwg` (в порядке вкладок). Это же использует `plot_set.ps1`.
- «Листов» — только на первом листе (ОД).

## 4. Массовая замена текста (вкл. СПДС)

1. `run_txtfix.ps1 -Files … -Find '<regex>' -Repl '<замена>' -Seen '<маяк>' -Dry` — посмотреть HIT (что будет заменено) и SEEN (похожие места, не попавшие под шаблон: отметки, координаты, иные формулировки).
2. Без `-Dry` на копиях → печать изменённых листов → показать → `-Apply`.
3. В прозе ОД менять формулировку осмысленно (не механически), согласовав со стилем образца.

## 5. Печать и сводный PDF

- **Перед печатью** (быстро, без печати):
  - `check_papers.ps1 -DwgDir … -Add` — форматы листов. Нестандартные, которых нет в «DWG To PDF» этого ПК, добавляются. `plot_set` делает это сам.
  - `check_sheet_numbers.ps1 -DwgDir …` — номера в штампах против имени файла. Нужно «Все номера листов в порядке». «ЛИШНИЙ МАКЕТ» — пустой или служебный макет в файле, его тоже напечатают.

- `plot_set.ps1 -DwgDir …\DWG -OutDir …\PDF\по листам -Titles @{…} -CoverPdf <обложка+титул.pdf> -SetPdf …\PDF\<шифр>.pdf`.
- Наименования PDF (`-Titles`) брать **из ведомости рабочих чертежей ОД этого комплекта**, а не из шаблона похожего сооружения: состав листов бывает разный.
- Актуальность старых PDF: перепечатать во временную папку и сравнить постранично (размер + попиксельно при 30 dpi). Время сохранения DWG позже печати — ещё не признак расхождения.
- Сводный = 2 страницы обложки/титула + листы по номерам. Отдельные листы — `PDF\по листам\NNN <наименование>.pdf`.
- Проверка: число страниц, размеры страниц против прошлой выдачи, кропы штампов (на листах А0 штамп не в углу — страница повёрнута).

## 6. Чек-лист сверки листов (типовые ошибки, найденные в практике)

- Заголовки видов, имена макетов и спецификаций от **соседнего сооружения** (копипаст): «В-4А-1» на листе В-5А-2 и т.п.
- Одно и то же значение по-разному на разных листах: длина трубы в спецификации ≠ надпись на профиле; марка бандажа ≠ диаметру трубы; отметки уровней колодца, перепутанные с другим сооружением.
- Материал в спецификации ≠ в примечаниях («цементно-грунтовая» vs «цементно-песчаная»).
- Элемент на чертеже без позиции в спецификации (решётка, геокомпозит).
- Номер ГОСТ с опечаткой (34027 vs 34028).
- Объёмы материалов: от какой площади считались (3D-поверхность vs площадь изделий), коэффициенты запаса — замечания заказчика именно сюда.
- Шифр в тексте: латинская/кириллическая буква (B vs В), опечатки при печати SHX («ИЗ4» → «И34»).
- Лист из одного комплекта отсутствует в папке другого (общий лист «Разрез» и т.п.).

## 7. Что записать в проект после работы

`<проект>\_claude\README.md`: состояние, решения пользователя (с датой), откуда взяты значения, что сделано скриптами и где они, открытые вопросы, резервные копии. Скрипты, специфичные для проекта (с его данными), — в `<проект>\_claude\скрипты\`; общие — сюда.
