# Каталог проверок

Серьёзность: 🔴 ошибка (блокирует выпуск), 🟡 предупреждение (выпуск после подтверждения).
Класс правки: **авто** / **текст** (с подтверждением) / **инж.** (только предложение) / — (без правки).
Готовность: ✅ скрипт есть и проверен; 🟨 есть основа, нужна доработка; ⬜ нет.

Этапы сервиса rd-ci определяются его спецификацией, а не готовностью скриптов:
[граница операций с документацией](https://github.com/yegori/rd-ci/blob/master/docs/11_mvp_scope.md).
rd-ci v0.4 — тонкий оркестратор Pi с этим пакетом; все методы проверки/генерации/правок и отчёты остаются здесь.
Для первой итерации автономного сервиса доступны задания проверки и PDF/сшивки; согласование исправлений через бот — следующая итерация.
Колонка «Правка» описывает возможный способ последующей коррекции, **не** разрешение применять её при проверке.

Примечания:
* **C1 «в модели»**: подписи соседних сооружений на общей подложке (Model) — не ошибка; ошибка — текст в макете
  или в объекте, видимом на листе. Для объектов модели, попадающих в видовой экран, нужна проверка «виден ли на листе» (⬜).
* **F2 поля**: номер листа часто — поле `$(substr,$(getvar,dwgname),1,3)`; проверять на копии с тем же началом имени.
* **F5**: разные записи относительных/абсолютных путей могут вести к одному файлу. Один basename или одинаковые
  хеши разных копий не доказывают общую цель. Правило относится к xref штампа, не к трассам/съёмке и прочим ссылкам.
  Номера/названия отдельных листов не обязаны совпадать; общая ссылка не гарантирует одинакового видимого оформления.
  Вложенные/неразрешённые ссылки и неподдержанный визуальный контроль — явные ограничения, не успешная проверка.

## Q — объёмы и спецификации (углублённые проверки; только предложения: правка — инж.)

Опыт ручной проверки В-5А-1 (сентябрь–октябрь 2026, `examples/arkhyz/В-5А-1/`). Общий принцип: **число в спецификации
пересчитать независимо из геометрии DWG** и сравнить; расхождение > 3–5 % — замечание с расчётом.

| № | Проверка | Как | Пример (В-5А-1) | Исполнитель |
|---|---|---|---|---|
| Q1 | Площадь по плану вместо откоса | штриховки покрытий на откосе: площадь в плане и по TIN 3D-линий котлована; k = 3D/план | противоэрозия 211,34 → 298,5 м² (k≈1,41); ГСИ на откосе 80,95 → 108,6 м² (k≈1,34); анкеры 95 шт по плану, нужно ≈134 | `export_dxf.ps1` + `slope_area.py` ✅ |
| Q2 | Число объектов в модели ↔ спецификация | тела/контуры/блоки по слоям; «узкие прямоугольники» (рёбра) | ряд 2 — 27 тел против 26 в спец.; ряд 3 — 23 ребра 0,17 м, 54,42 пм против 4 шт ГСИ-М | `layer_stats.py` ✅ |
| Q3 | Объёмы 3D-тел | MASSPROP по слоям (ezdxf тела SAB не читает) | ряд 2 — 47,91 м³; бетон колодца ≈44,8–45,3 м³ против 37,2 в спец. (исправлено 07.10 → 44,7) | `massprop.ps1` ✅ |
| Q4 | Коэффициенты и нормы | один и тот же материал — одинаковые коэффициенты/нормы на разных листах | камень ×1,05 на л.7 есть, на л.6 нет; скобы CL/50 4,32 г (л.6) против 4,70 г (л.7) | ⬜ (сверка таблиц СПДС, `McTable`) |
| Q5 | Двойной учёт | одна работа в спецификациях двух листов под разными названиями | ЦПС 13,5 м³ (л.5) + «цементно-грунтовая перемычка» 11,32 м³ (л.2) | ⬜ (словарь синонимов работ) |
| Q6 | Нет объёмов | работы из текста/разрезов без строки в спецификациях | обратная засыпка пазух, вывоз грунта (п.6 ОД), основание трубы (щебень ≈34 м³, геотекстиль ≈344 м²), нет ведомости земляных работ на л.3 | ⬜ (чек-лист типовых работ по типу сооружения) |
| Q7 | Арифметика спецификаций | кол-во × масса ед. = масса; итоги; ведомость стали = сумма позиций | — (проверялось вручную; ошибок в 07.10 не найдено) | ⬜ (таблицы СПДС → числа) |
| Q8 | ОД ↔ листы | ссылочные документы ⊇ упомянутые на листах ГОСТ/СП; ведомость спецификаций ↔ реальные таблицы; значения в тексте ОД (длины, защитные слои) ↔ чертежи | нет СП 20/131/45/72, ГОСТ 26633/8267/23279; «Ведомость земляных работ» в ведомости, а на листе нет; длина 88,11 против 4,2+61+23,6=88,8 | ⬜ (`run_txtfix -Dry` по `ГОСТ|СП|ТУ` + сверка) |

Методика ручной проверки (порядок): PDF → PNG (`pdf_tools.py render`, текст SHX не извлекается) и выписать спецификации →
DWG → DXF, найти слои объектов (`layer_stats.py` по всем слоям, потом по нужным) → пересчитать площади/длины/число/объёмы →
сводная Excel (openpyxl, пересчёт через Excel COM): «спец. / DWG / расхождение / замечание» со ссылками на листы PDF.
Слои и блоки — свои у каждого проектировщика; для автоматизации их нужно задавать в паспорте раздела (`quantities:` — слой → позиция спецификации).

Источник опыта: `10_playbook.md` (чек-лист сверки листов), `12_arkhyz_test_cases.md` и проектные записки Архыза (`examples/arkhyz/`).
