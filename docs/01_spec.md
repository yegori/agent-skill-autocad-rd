# Спецификация сервиса rd-ci (v0.2)

## 1. Назначение

Автоматическая проверка разделов рабочей документации (комплектов DWG в AutoCAD/СПДС) перед выпуском, по аналогии
с CI/автотестами перед деплоем. Сервис находит несоответствия, предлагает и (по команде) вносит правки, формирует
лист «Общие данные», сшивает комплект и сообщает статус.

Пользователь сейчас — один (ведущий инженер); уведомления и согласование ОД — группа объекта в Telegram (коллеги).

## 2. Термины

| Термин | Значение |
|---|---|
| Проект (объект) | Корневая папка объекта, напр. «Архыз ВО\06 РД\1 Этап». Может содержать много разделов, сооружений и шифров. |
| Раздел | Папка с однотипными сооружениями, напр. «Водопропуски», «площадной дренаж». |
| Сооружение / комплект | Одно сооружение = один шифр (ИЗn), напр. В-4А-2 / ИЗ2. |
| Версия | Папка выдачи с датой: `<дата> - 01_B590.110504.1.6-ИЗn` (DWG + PDF). Аналог коммита. |
| Итерация правок | Новая папка `<дата> - …-ИЗn (испр.N)`, созданная сервисом при правках. |
| Паспорт | Настройки проверки: `_claude\project.yaml` (проект) и `_claude\section.yaml` (раздел). |
| Реестр | `ошибки.xlsx` — все замечания версии с номерами, статусами и историей. |

## 3. Жизненный цикл версии

```
метка ПРОВЕРИТЬ.txt → в очереди → проверка листов ──🔴──→ правки (испр.N) → перепроверка ─┐
                                          │                                              │
                                          └──🟢 / 🟡+подтверждение ←─────────────────────┘
                                                    ↓
                                       черновик ОД → согласование в группе → сшивка → итоговая проверка
                                                                                          ↓
                                                                        🟢 / 🟡+подтверждение → выпущено
```

1. **Триггер — файл-метка** `ПРОВЕРИТЬ.txt` в папке версии (не просто появление папки — чтобы не проверять полуготовое).
   Необязательное содержимое: `что меняли:`, `сравнить с:`, `собрать PDF:`. Сервис переименовывает метку в
   `ПРОВЕРЯЕТСЯ.txt` (защита от двойного запуска), по окончании убирает.
2. **Снимок.** Перед проверкой ждём «тишины» синхронизации Яндекс.Диска (N минут без изменений), копируем версию
   на локальный диск ПК. Исходная папка при проверке не меняется.
3. **Проверка листов (без ОД).** Структура, оформление, печатаемость, содержание (см. `03_checks.md`).
   **Пока есть 🔴 — ОД не строится**: сначала листы приводятся к консистентности.
4. **Правки** — только по команде (бот или ПК), в новой папке `(испр.N)`; затем автоматическая перепроверка.
5. **Черновик ОД** — скриптом из паспорта и данных листов, когда листы 🟢 (или 🟡 с подтверждением).
6. **Согласование ОД** — в группе объекта (см. п. 7).
7. **Сшивка** — штамп, обложка, номера, «Листов», печать, сводный PDF.
8. **Итоговая проверка** собранного комплекта → статус.

## 4. Статусы и пометки

| Статус | Значение | Выпуск |
|---|---|---|
| 🟢 | ошибок и предупреждений нет | можно |
| 🟡 | только предупреждения | только после подтверждения человеком в боте («Подтвердить выпуск») |
| 🔴 | есть ошибки | нельзя |

* В папке версии при 🔴 (и 🟡 без подтверждения) — метка `!НЕ ВЫПУСКАТЬ — см. _claude.txt`; при 🟢 меток нет.
  Иных служебных файлов в папке версии нет (она уходит заказчику).
* В `<раздел>\_claude\проверки\<версия>\`: `ошибки.xlsx`, `отчёт.html` (с кропами), `статус.txt`, журналы, PDF-кандидаты.
* В `статус.txt` и реестре фиксируется, кто и когда подтвердил выпуск / утвердил ОД.

## 5. Правки и версии

* Классы правок: **авто** (имена файлов/макетов, номера листов не-поля, пути внешних ссылок, форматы, мусор) —
  одной командой; **текстовые** (чужой код сооружения, словарь нормативов и терминов) — по списку с подтверждением;
  **инженерные** (значения, расходящиеся между листами) — только предложение с обоснованием, решает человек
  (принять / отклонить / своё значение).
* Каждая итерация правок — **новая папка** `(испр.N)`, всегда от последней. Пока идут правки, на исходной — метка
  «заблокировано — идут правки».
* Когда итерация стала 🟢 (или 🟡 с подтверждением) — исходная и промежуточные версии **переносятся в архив**
  (`<сооружение>\_claude\архив версий\`), не удаляются.
* Все правки — в реестре: что было/стало, кто одобрил, когда; оригиналы — в резервной копии.
* **Новая дата при невыпущенной текущей версии — ошибка процесса.** Новая версия не создаётся, сервис продолжает
  правки в текущей. Если коллега всё же положил новую папку — сервис её не берёт, кладёт метку
  «заблокировано: версия X ещё не выпущена» и пишет в группу.

## 6. Реестр ошибок

* Каждая ошибка имеет сквозной номер в пределах сооружения (`В-4А-2-0007`), живущий через все версии/итерации.
* Сопоставление между версиями — гибридное: основной ключ «проверка + файл/лист + handle объекта»; если handle не
  найден — нечёткое по «проверка + лист + нормализованный текст».
* Статусы: новая / осталась / исправлена / вернулась.
* Поля: №, лист, место (макет/объект/ячейка), проверка, серьёзность, было, предложение, обоснование, класс правки,
  статус, кто/когда решил.

## 7. Telegram-бот

* Работает на ПК сервиса (опрос Telegram; входящие порты не нужны).
* **Группы объекта** (одна группа = проект или раздел проекта; привязка командой `/bind <раздел|проект>` — бот сам
  записывает ID группы в паспорт; `/unbind`):
  * уведомления: только статус (старт, итог 🟢/🟡/🔴 с кратким списком);
  * черновик ОД на согласование: PDF черновика + «Утвердить» / «Нужны правки». Утвердить может **любой участник
    группы объекта**; повторное подтверждение + 5 минут на отмену; «Нужны правки» → комментарий в реестр, задача оператору;
  * файлы по запросу: `/pdf <сооружение> [лист]`, `/report <сооружение>`.
* **Личный чат** (белый список, пока — один пользователь): `/status [раздел|сооружение]`, `/errors`, `/run`, `/fix <номера>`,
  кнопки правок по классам, «Подтвердить выпуск» для 🟡, `/queue`, `/cancel`.
* Лимит Telegram на файл бота — 50 МБ: большие комплекты — по частям/листам или путь на Яндекс.Диске.

## 8. Права

| Действие | Кто |
|---|---|
| Метка `ПРОВЕРИТЬ.txt` | любой, кто работает в папке |
| Просмотр статусов, PDF, отчётов | участники группы объекта; личный чат — белый список |
| Утверждение ОД | любой участник группы объекта (с подтверждением) |
| Правки листов, подтверждение 🟡, очередь | белый список (пока один пользователь) |

## 9. Регрессия (после MVP)

Сравнение с предыдущей выпущенной версией: какие листы изменились (попиксельно по PDF + по тексту), изменения вне
заявленных в `что меняли:` — предупреждения. Детализация «где на листе» (картинка различий) — по отдельному запросу.

## 10. Не цели

* Сервис не принимает инженерных решений — только подсвечивает противоречия и предлагает.
* Не правит исходную версию без команды; не трогает папки, уже переданные заказчику.
* Не взрывает объекты СПДС (правка — через API).
