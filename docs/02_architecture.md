# Архитектура rd-ci

## 1. Площадка

* Выделенный ПК: **Windows 10 Pro x64**, удалённый доступ (RDP). Лицензии AutoCAD 2024 и СПДС GraphiCS 2023 — на этом ПК.
* Клиент Яндекс.Диска синхронизирует папки проектов (только нужные проекты — выборочная синхронизация).
* Рабочий диск для снимков и журналов: `C:\rd-ci\work\` (короткий латинский путь — см. «Грабли»).
* Доступ в интернет (Telegram API, исходящие соединения).

## 2. Компоненты

```
 Яндекс.Диск ──синхр.──► папки проектов
                              │  ПРОВЕРИТЬ.txt
                              ▼
  [наблюдатель] ──задание──► [очередь] ──► [раннер пайплайна] ──► исполнители:
        ▲                       ▲              │                   • accoreconsole (чтение/правка/печать DWG)
        │                       │              │                   • acad.exe + плагин SpdsText (объекты СПДС)
  [Telegram-бот] ◄──статусы─────┴──────────────┤                   • Python: PDF (pymupdf), отчёты, реестр (openpyxl)
        │  команды /run /fix /bind …           ▼
        └────────────────────────────► реестр/отчёты в <раздел>\_claude\проверки\<версия>\
```

| Компонент | Реализация | Примечание |
|---|---|---|
| Наблюдатель | Python-процесс (опрос раз в 1–2 мин) или Планировщик заданий Windows | ищет `ПРОВЕРИТЬ.txt` в разделах, перечисленных в паспортах; ждёт тишины синхронизации |
| Очередь | SQLite (`C:\rd-ci\state.db`) | задания, статусы, история запусков, сопоставление ошибок, привязки групп |
| Раннер | Python | читает паспорта, гоняет этапы, вызывает исполнители, пишет реестр и отчёт |
| Исполнители | существующие PowerShell-скрипты (`toolkit`) + плагин SpdsText | см. п. 4 |
| Бот | Python + aiogram (long polling) | токен — в переменной окружения/файле вне Яндекс.Диска |
| Служба | Планировщик Windows «при входе/при старте» или NSSM-служба для бота и наблюдателя | автоперезапуск при падении |

Стек: Python 3.12+, PowerShell 7, aiogram, openpyxl, pymupdf, ezdxf, PyYAML; плагин SpdsText (C# 5, csc из .NET Framework 4).

## 3. Правило одного AutoCAD

* **acad.exe и accoreconsole никогда не запускаются одновременно** (было падение acad.exe с Access Violation).
* acad.exe (СПДС) — строго по одному заданию. accoreconsole — тоже последовательно (параллельные копии на тяжёлых
  Civil 3D-файлах зависали).
* Раннер держит глобальную блокировку «AutoCAD занят»; бот при этом отвечает «в очереди, позиция N».

## 4. Исполнители (что уже есть)

| Задача | Скрипт (`toolkit\`) | Проверен |
|---|---|---|
| Общие функции (копии с сохранением начала имени, cp1251 .scr, скобки, занятость файла, LISP макетов/печати) | `common.ps1` | да |
| Разведка текстов/атрибутов/объектов | `dump_layout_texts.ps1` | да |
| Форматы листов (+ добавление в PMP) | `check_papers.ps1`, `add_pmp_size.py` | да |
| Номера листов (поле/атрибут/текст) | `check_sheet_numbers.ps1` | да |
| Перенумерация (MTEXT/атрибут) | `renum_stamp.ps1`, `set_sheet_attr.ps1` | да |
| Имена/удаление макетов | `fix_layouts.ps1` | да |
| Печать комплекта + сводный PDF | `plot_set.ps1`, `merge_set.py` | да |
| Найти/заменить текст вкл. СПДС; свойства объектов СПДС (`-Mode props`) | `spds_text\run_txtfix.ps1` + `SpdsText.cs` | да |
| Сборка ОД по образцу | `od\build_od.ps1`, `od_lib.py`, генератор проекта | да |

Нужно доработать для сервиса: единый машиночитаемый вывод (JSON) вместо текста; коды возврата; таймауты и снимок
окна AutoCAD при зависании; запуск без интерактивного рабочего стола (проверить работу acad.exe в службе — скорее
всего нужен вход пользователя на ПК, т.е. запуск в его сеансе).

## 5. Хранение

| Где | Что |
|---|---|
| папка версии | только содержимое выдачи + метки `ПРОВЕРИТЬ/ПРОВЕРЯЕТСЯ`, `!НЕ ВЫПУСКАТЬ`, «заблокировано» |
| `<раздел>\_claude\section.yaml`, `<проект>\_claude\project.yaml` | паспорта |
| `<раздел>\_claude\проверки\<версия>\` | `ошибки.xlsx`, `отчёт.html`, `статус.txt`, журналы, PDF-кандидаты |
| `<сооружение>\_claude\архив версий\` | заменённые версии |
| `C:\rd-ci\work\` | снимки, рабочие копии, временные PDF |
| `C:\rd-ci\backup\` | оригиналы перед каждой правкой (+ ротация) |
| `C:\rd-ci\state.db` | очередь, история, сопоставление ошибок, привязки групп |

## 6. Отказоустойчивость

* Таймауты на каждый вызов AutoCAD; при превышении — снимок окна (видно модальный диалог), убить процесс, задание → «ошибка исполнителя», уведомление.
* Повтор при падении acad.exe (1 раз), затем ошибка.
* Файлы, занятые пользователем/синхронизацией (`Test-FileFree`) — откладывать, не ломать.
* Метка `ПРОВЕРЯЕТСЯ.txt` + запись в БД — восстановление после перезапуска ПК.
* Все известные ловушки — `11_pitfalls.md` (кириллица в путях, here-string без перевода строки, регистронезависимые
  переменные PowerShell, PROXYNOTICE, поля от имени файла, нестандартные форматы и т.д.).

## 7. Безопасность

* Токен бота — вне синхронизируемых папок.
* Команды правок — только из белого списка Telegram ID; утверждение ОД — участники привязанной группы.
* Сервис пишет только в: новые папки `(испр.N)`, `_claude`, архив, метки; исходную версию — только метками.
